TESK API 1.2.0 is the first release of TESK API since 1.1 (2021) and the first one published from this repository's release workflow: a signed `elixircloud/tesk-api:1.2.0` image on Eclipse Temurin 8, scanned before it is published. It brings TES-conformant task states, outputs and cancellation responses, filtering of listed tasks by name, decimal CPU cores, optional authorisation by a user-info claim instead of groups, a lossless record of task creators, an image that runs as a non-root user, and the Swagger UI off by default. Several changes need action from operators or clients: read the [upgrade notes](https://tesk.readthedocs.io/en/latest/tesk-api/upgrading/#to-120) before you upgrade, and upgrade TESK API before the taskmaster ([tesk-core v0.11.0](https://github.com/elixir-cloud-aai/tesk-core/releases/tag/v0.11.0)).

## Breaking changes

- The Swagger UI and `/swagger-resources` are off by default; set `TESK_API_SWAGGER_UI_ENABLED=true` to serve them (#79, #80)
- The Swagger UI gets no OAuth client secret any more; `TESK_API_SWAGGER_OAUTH_CLIENT_SECRET` is deprecated and ignored, register the Swagger UI as a public client (#106, #108)
- Task creators are recorded without loss, in the label `creator-user-hash` and the annotation `creator-user-id`, so that any user ID works, also one longer than 63 characters or with characters that labels don't allow; tasks created before the upgrade no longer belong to their creators unless `TESK_API_AUTHORISATION_LEGACY_USER_LABELS=true` is set for the transition (#119, #122)
- The image runs as the user `tesk` (UID 1000, group 0) instead of `root`; kubeconfig files go to `/home/tesk/.kube/config` (#83, #89)
- The taskmaster's job owns the task's ConfigMap, so TESK API needs `delete` on `jobs` (and on `configmaps` where `OwnerReferencesPermissionEnforcement` is on); tasks that Kubernetes is deleting are gone from `GET /tasks` (#117, #118)
- The state of a task comes from all its jobs: a failed executor gives `EXECUTOR_ERROR`, a missing executor job `SYSTEM_ERROR`, and executor jobs aren't retried unless the taskmaster sets `EXECUTOR_BACKOFF_LIMIT` (#104, #107)
- `GET /tasks` refuses a `page_size` below 1 or above 2048, and malformed or expired page tokens with `400 Bad Request` instead of `500` (#114, #115)
- `POST /tasks/{id}:cancel` answers with `{}` instead of an empty body (#37, #87)
- Without other settings, TESK API runs the taskmaster and filer images that tesk-core publishes (`docker.io/elixircloud/tesk-core-taskmaster` and `-filer`, `0.11.0`) instead of `eu.gcr.io/tes-wes/*:v0.10.0`; the Helm chart of TESK sets its own (#123, #124)
- `resources.cpu_cores` and `disk_gb` must be greater than 0 and `ram_gb` at least `0.000001`: `0` and negative numbers, which were accepted before, are refused with `400 Bad Request`; leave a field out for no requirement (#128, #130)

## Features

- Filter listed tasks by name prefix (`name_prefix`) (#24, #113)
- Optional authorisation by a claim of the user info instead of group membership (#78, #116)
- `TESK_API_SERVICE_INFO_PUBLIC` makes `GET /service-info` public (default) or token-protected (#62, #69)
- Release images are tagged `X.Y.Z` (and `latest`), signed with Sigstore and announced to Pubgrade if it is configured, from the `release` environment (#61, #68, #120, #121)

## Security

- Dependencies flagged by the image scan updated (#60, #67, #102, #103)
- The Maven distribution of the wrapper is verified by its checksum (#97, #98)

## Fixes

- Decimal numbers of CPU cores, e.g. `0.5`, are accepted instead of being cut to `0` (#44, #90)
- `logs[0].outputs` is an empty array instead of missing, and `logs` sent with a new task are ignored (#36, #112)
- `GET /tasks/{id}` and `POST /tasks/{id}:cancel` answer `404 Not Found` instead of `500` for jobs without labels (#125, #130)
- Tasks with `ram_gb` are created also when the JVM's default locale writes numbers with a decimal comma (#128, #130)
- New tasks are `QUEUED` instead of `SYSTEM_ERROR` until Kubernetes has created the taskmaster's pod, and tasks whose taskmaster doesn't run yet are really cancelled (Kubernetes ends their job) instead of starting later all the same (#126, #132)
- The configured group prefix, groups, admin subgroup and suffix are matched as plain text, so that characters such as `.` no longer match any character (#134, #135)
- Service info reports the TES type version as `"1.0.0"` instead of `"1.0"` (#136, #138)
