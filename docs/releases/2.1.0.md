TESK API 2.1.0 makes the pods of tasks admissible in namespaces that enforce the `restricted` Pod Security Standard or have a `ResourceQuota` on `limits.cpu` (e.g., those of the CERIT-SC cluster): new settings give the taskmaster's and the executors' pods and containers security contexts (off by default), and the taskmaster and the executors get CPU and memory requests and limits by default. It runs the taskmaster and filer of [tesk-core 0.13.0](https://github.com/elixir-cloud-aai/tesk-core/releases/tag/v0.13.0) by default instead of 0.11.0, so that `ignore_error`, output file logs and the filers' resource limits work without extra settings, and it removes the alias `/v2/api-docs` of the API description, as announced in 2.0.0. Clients that still read `/v2/api-docs` must move to `/v3/api-docs`, and deployments should check the new default resources and images against their quotas and `LimitRange`s: read the [upgrade notes](https://tesk.readthedocs.io/en/latest/tesk-api/upgrading/#to-210) before you upgrade.

## Breaking changes

- The alias `/v2/api-docs` of the API description, deprecated in 2.0.0, is removed: it gives `404 Not Found`, or `401 Unauthorized` without a token with the `auth` profile; the same OpenAPI 3.1 description is at `/v3/api-docs` and `/v3/api-docs.yaml` (#188, #206)
- The taskmaster's container requests CPU 100m and memory 128Mi and is limited to CPU 500m and memory 256Mi by default, and executors of tasks without `resources.cpu_cores` request and are limited to 1 CPU; in namespaces with a `LimitRange` that refuses these values, set `TESK_API_TASKMASTER_RESOURCES` and `TESK_API_TASKMASTER_EXECUTOR_DEFAULT_CPU` to fit, or empty for none (#209, #210)
- Executors of tasks that set `resources.ram_gb` get it as their memory limit also when the task sets `resources.cpu_cores`, so executors that use more memory are stopped (`OOMKilled`) (#209, #210)
- Without other settings, TESK API runs the taskmaster and filer of tesk-core 0.13.0 instead of 0.11.0, whose filers request CPU 100m and memory 128Mi and are limited to CPU 1 and memory 512Mi by default (`FILER_RESOURCES` of the taskmaster changes them); deployments that set `TESK_API_TASKMASTER_IMAGE_VERSION` and `TESK_API_TASKMASTER_FILER_IMAGE_VERSION`, e.g. with the Helm chart of TESK, keep theirs (#211, #213)

## Features

- Security contexts of the taskmaster's and the executors' pods and containers, e.g. for namespaces that enforce the `restricted` Pod Security Standard, as JSON objects with the fields of the Kubernetes API, checked at startup: `TESK_API_TASKMASTER_POD_SECURITY_CONTEXT`, `TESK_API_TASKMASTER_SECURITY_CONTEXT`, `TESK_API_TASKMASTER_EXECUTOR_POD_SECURITY_CONTEXT` (on top of the one from `CONFIGMAP`) and `TESK_API_TASKMASTER_EXECUTOR_SECURITY_CONTEXT`; unset by default (#209, #210)
- The taskmaster's resources and the executors' default CPU are settings of their own, `TESK_API_TASKMASTER_RESOURCES` and `TESK_API_TASKMASTER_EXECUTOR_DEFAULT_CPU`, checked at startup (#209, #210)

## Fixes

- Executors of tasks with `cpu_cores` and `ram_gb` above a namespace's default memory limit start, as their memory limit is their `ram_gb` instead of the `LimitRange`'s default, which was below their request (#209, #210)
